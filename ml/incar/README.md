# ทดสอบในรถ (ก่อนตัดสินใจ fine-tune)

วัดว่า firmware ที่อยู่บนบอร์ดตอนนี้ (**0.3.18-p50**) ใช้ได้จริงในรถไหม
ด้วยผลจากบอร์ดเอง (`/api/status` + บันทึก Trip ในบอร์ด) ไม่ใช่การจำลอง แล้วค่อยตัดสินว่าต้อง fine-tune โมเดลตาหรือไม่

> **สถานะ 4 พ.ย.:** ผู้ใช้เลือกใช้โค้ดใน repo แฟลช 0.3.18-p50 ทับ 0.3.15-p15 ของเพื่อน ยอมรับผลรถจอดแล้ว ไม่ fine-tune
> - ค่าที่ตั้ง: `P_CLOSED_ON/OFF` 0.5 · `PERCLOS_LEVEL2` 0.40 · ตัดระดับ TIRED
> - รถจอด กลางวัน: ไม่ใส่แว่น (0.3.16) เตือน 6/6 · ใส่แว่น (0.3.18) เตือน 6/6 ตามบันทึกในบอร์ด · จอ OLED ตรงกับสถานะทุกท่า (0.3.17)
> - ข้อจำกัดที่ยอมรับ: หันหัวแล้วเตือนผิดได้ (บอร์ดตัดแก้มเป็นตา ขึ้นกับกล้องและตำแหน่งนั่ง) · PERCLOS ≥ 0.40 ทำให้ `SLEEPY` และเสียงค้างหลังลืมตาได้ราว 11 วิ · ตาปรือนาน 2 วิเตือนเหมือนหลับตา
> - ยังไม่รู้สาเหตุ: รอบสุดท้ายบอร์ดอ่านตาปิดหลังบี๊บ 3–6 วิ (คนช้าหรือบอร์ดตามหลัง) · เว็บบอร์ดค้างเป็นช่วงๆ บางรอบ · ยังไม่ได้ทดสอบกลางคืน
> - ขับจริงรอบแรก (7.5 นาที ใส่แว่น กลางวัน): เตือน 9 ครั้ง ผู้ใช้หลับตาจริงระหว่างขับบางช่วงโดยยังไม่ได้ยืนยันเวลา จึงแยกจริงหรือผิดไม่ได้ทั้งหมด · จากภาพตา 3 ครั้งเป็นการหันหัว 2 ครั้งเป็นแสงจ้าหรือมืดจัด · ห้ามใช้รอบนี้ fine-tune โดยไม่ตรวจป้าย และห้ามหลับตาตอนรถวิ่ง
> - ผู้ใช้ลอง microsleep 2 วิแล้วกลับมาที่ 3 วิ เพราะกล้องและโมเดลยังตรวจไม่ดีพอ (เล่นซ้ำรอบขับที่ 2 วิได้เสียงดังค้าง 11 ครั้ง)
> - flash เดิมของเพื่อนสำรองไว้ที่ `Desktop\esp32-flash-backup\DrowsyFW_0.3.15-p15_flash16MB_2026-11-04.bin`

## เตรียม

1. **ไม่ต้องแฟลช** ใช้ 0.3.18-p50 ที่อยู่บนบอร์ด · ตอนเริ่มสคริปต์ต้องขึ้น `บอร์ด fw 0.3.18-p50` และ `/eyes.raw มี (เก็บภาพตาด้วย)`
2. ติดกล่องตำแหน่งจริง: กระจกหน้า ฝั่งซ้ายคนขับ ใกล้กระจกมองหลัง แถว IR อยู่บน
3. เปิดบอร์ด (ไม้จิ้มฟันดัน SW1) ต่อโน้ตบุ๊กเข้า WiFi `Drowsy-XXXX` เปิด `http://192.168.4.1` นั่งท่าขับ
   ดูภาพสดว่ามีกรอบหน้าเขียวและกรอบตาขึ้นสม่ำเสมอ ถ้าหาหน้าไม่เจอ แก้มุม/ตำแหน่งกล่องก่อน
4. โน้ตบุ๊กเปิดเสียง (สคริปต์พูดบอกท่าเป็นภาษาอังกฤษ + บี๊บ: 2 ครั้งเสียงสูง = หลับตา, 1 ครั้งเสียงต่ำ = ลืมตา)

## รอบทดสอบตอนจอด (~3.7 นาที) ⚠️ รถจอดเท่านั้น

```bash
cd ml/incar
../.venv/Scripts/python.exe cartest.py --name 2026-11-05_day_noglasses --person frank --light day --glasses none
```

- ช่วง A (2.2 นาที, ไม่มีการหลับตา): มองถนน · เหลือบมองกระจก 3 ครั้ง · ก้มดูมือถือ · กะพริบตาปกติ 40 วิ · หรี่ตา → นับ**การเตือนผิด**
- ช่วง B (1.5 นาที): หลับตา 5 วิ × 5 ครั้ง สลับลืมตา 10 วิ + หลับตา 8 วิ → นับว่า**เตือนครบไหม**และเตือนหลังหลับตากี่วินาที
- ทำตามเสียง ไม่ต้องรีบ สคริปต์ตัดช่วงเปลี่ยนท่าทิ้งเอง · กด Ctrl+C หยุดได้ ข้อมูลที่ได้ยังบันทึก

ทำซ้ำอย่างน้อย: กลางวันไม่ใส่แว่น · กลางวันใส่แว่น (ถ้าคนขับใส่) · ครึ้ม/เย็น · กลางคืน (IR บนบอร์ดอ่อน อาจหาหน้าไม่เจอ ดูประเด็นค้าง #5)

## อ่านผลแล้วตัดสินใจ

สคริปต์พิมพ์ผลท้ายรอบและเขียน `report.json` · ตัดสินแบบนี้:

| ผล | ความหมาย | ทำต่อ |
|---|---|---|
| หลับตาเตือน 6/6 · ช่วง A เตือนผิด 0 · ขับจริงเตือนผิดน้อย | firmware นี้ใช้ได้ | **ไม่ต้อง fine-tune** สาธิตได้ |
| ไม่เตือน และขึ้น "หาหน้าไม่เจอเกิน 40%" | ปัญหาหาหน้า/มุมกล้อง | fine-tune ไม่ช่วย → แก้ตำแหน่งกล่อง/แสง |
| ไม่เตือน และขึ้น "เห็นหน้าแต่ตอบว่าตาเปิด" (P ระหว่างหลับต่ำ) | โมเดลตาพลาดกับกล้องเรา | **fine-tune** |
| ลืมตาอยู่แต่เตือน, P ตอนลืมตาสูง | เกณฑ์ต่ำเกิน | ลองขยับ `P_CLOSED_ON` ใน `config.h` ด้วย `replay.py --on --off` ก่อน fine-tune |
| เหลือบมอง 2–3 วิ แล้วขึ้น "ไม่มองถนน" | เกณฑ์ Distraction 3 วิ | ไม่เกี่ยวกับโมเดลตา ดู `DISTRACTION_MS` |

ผลจากคนเดียวยังไม่พอสรุปว่าใช้ได้กับทุกคน ถ้ามีเวลาให้เพื่อนนั่งอีกคน (ขอความยินยอมก่อนเก็บภาพ)

## ถ้าผลไม่ผ่านเพราะโมเดลตา: fine-tune

ใช้ภาพตาใน `eyes.npy` ที่ `cartest.py` เก็บจาก `/eyes.raw` · ถ้าเว็บบอร์ดค้าง ภาพช่วงนั้นจะหาย ให้เก็บรอบเพิ่ม
`replay.py` อ่านเกณฑ์จาก `config.h` ใน repo หรือระบุ `--on` / `--off` เอง · ทุกคำสั่งรันใน `ml/incar` ด้วย `../.venv/Scripts/python.exe`

1. **ตรวจป้าย** `review.py` → <http://127.0.0.1:8797/> เลือกรอบ เปิด "เฉพาะที่น่าสงสัย" แล้วกดภาพที่ป้ายผิด (ตามท่า → เปิด → ปิด → ทิ้ง) บันทึกเองทันที
   ป้ายที่ train ได้มีแค่ เปิด/ปิด · เหลือบมอง หรี่ตา กะพริบ ขับจริง ไม่เข้า train เว้นแต่แก้เป็นเปิด/ปิดเอง
2. **แบ่งรอบ** อย่างน้อย train 2 รอบ · val 1 รอบ · test 1 รอบที่ไม่เคยใช้ (คนละวัน/แสง หรือคนละคน) · ห้ามรอบเดียวกันอยู่สองชุด
3. **train**
   ```bash
   ../.venv/Scripts/python.exe finetune.py --train รอบ1 รอบ2 --val รอบ3 --test รอบ4 --run 2026-11-06_a
   ```
   CPU ราว 5–15 นาที · ได้ `ml/output/incar/<run>/report.md` เทียบ recall ตาปิด / ตาเปิดที่ทายเป็นปิด ของโมเดลใหม่กับโมเดลบนบอร์ด ทีละตา ที่เกณฑ์ 0.3 และ 0.5 พร้อม MRL test (ต้องไม่ตกมาก)
4. **เล่นซ้ำก่อนแฟลช**
   ```bash
   ../.venv/Scripts/python.exe replay.py รอบ4 --run 2026-11-06_a           # เกณฑ์จาก config.h
   ../.venv/Scripts/python.exe replay.py รอบ4 --run 2026-11-06_a --on 0.5 --off 0.3   # ลองเกณฑ์อื่น
   ```
   ดูบรรทัด `new` เทียบ `board_actual` (ผลจริงของบอร์ด): ต้องเตือนครบมากขึ้น และเตือนผิดไม่เพิ่ม
   แถว `board` ควรใกล้ `board_actual` ถ้าห่างกันมาก replay เห็นเฟรมไม่พอ (ดึง /eyes.raw ไม่ทัน) อย่าเชื่อตัวเลขมาก
5. **ใส่บอร์ด** คัดลอก `ml/output/incar/<run>/model_data.h` ไปทับ `~/Documents/Arduino/DrowsyFW/eye_model_data.h` → เปลี่ยน `FW_VERSION` → compile → แฟลช → ทดสอบในรถอีกรอบด้วย `cartest.py`
   (ถ้าเปลี่ยนเกณฑ์ ให้แก้ `P_CLOSED_ON` / `P_CLOSED_OFF` ใน `config.h` ด้วย)

ลองทั้งชุดบน PC ได้ด้วยรอบจาก `fake_board.py` และ `--quick` (1 epoch ผลไม่มีความหมาย)
