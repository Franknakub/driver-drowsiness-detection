# 🔴 BLOCKER

## B1 — บัซเซอร์จะดังตลอดเวลา ปิดไม่ได้

**Netlist:** `5V ; U1.1 ...` · `GND ; U1.2 ...` · `GPIO14 ; U1.3 U5.37 U5.38`

โมดูล Active Buzzer ที่จะใช้ขับด้วย **S8550 = ทรานซิสเตอร์ PNP** ต่อแบบ high-side (emitter → VCC) และสเปกระบุ *"When the I/O port input low, the buzzer Sound"* → active-LOW

ปัญหา: บอร์ดจ่าย **VCC = 5V** แต่ ESP32-S3 ขับ I/O ได้สูงสุด **3.3V**

| สถานะ GPIO14 | V_EB ของ S8550 | ผล |
|---|---|---|
| LOW (0V) | 5.0V | ทรานซิสเตอร์นำ → บัซเซอร์ดัง (ตามต้องการ) |
| HIGH (3.3V) | **5 − 3.3 = 1.7V** | ยังมากกว่า V_BE(on) ≈ 0.7V → **ทรานซิสเตอร์ยังนำอยู่ → บัซเซอร์ยังดัง** |

**สั่งให้เงียบไม่ได้เลย** และตอน boot ที่ GPIO14 เป็น high-Z ก็จะดังด้วย

**วิธีแก้:** ย้าย `U1.1` จาก net `5V` → net `3V3`
สเปกโมดูลระบุ *"can be directly connected with the 5V microcontroller and 3.3V microcontroller"* → รองรับ 3.3V อยู่แล้ว เมื่อ VCC = 3.3V และ GPIO = 3.3V จะได้ V_EB = 0V → ปิดสนิท

## B2 — ขั้ว OLED สลับ เสียบแล้วจอพัง

**Netlist P1:** pin1 = `3V3` · pin2 = `GND` · pin3 = `GPIO01` · pin4 = `GPIO42`

โมดูล OLED 0.96" SSD1315 ที่จะใช้ silkscreen เรียงว่า **`GND` `VCC` `SCL` `SDA`**

| ตำแหน่ง | บอร์ดเรา (P1) | โมดูล OLED | ผล |
|---|---|---|---|
| 1 | 3V3 | **GND** | ❌ 3.3V เข้าขา GND |
| 2 | GND | **VCC** | ❌ GND เข้าขา VCC |
| 3 | GPIO1 | SCL | ✅ ใช้ได้ |
| 4 | GPIO42 | SDA | ✅ ใช้ได้ |

เสียบตรงๆ = **ป้อนกลับขั้ว จอเสียทันที**

**วิธีแก้:** สลับ P1 pin1 ↔ pin2 ในschematic (pin1 = GND, pin2 = 3V3)
ขา 3/4 ไม่ต้องแก้ — SCL/SDA บน ESP32 remap ได้อิสระ กำหนดใน firmware ได้เลย

---

## B3 — designator ไม่ตรงกันระหว่าง schematic กับ PCB

- Schematic มี **`C5`** (100nF, ต่อกับ GPIO41/SW1/R10)
- PCB มี **`C3`** แทน

จำนวนเท่ากัน (33/33) แต่ชื่อไม่ตรง → PCB ยังไม่ได้ sync กับ schematic รอบล่าสุด

**วิธีแก้:** กด `Design → Import Changes from Schematic` → `Apply Changes` **ผ่าน GUI เท่านั้น** (API `importChanges()` คืน `true` แต่ไม่ทำงานจริง — บั๊กที่บันทึกไว้แล้ว)

## B4 — Schematic ERC: ผลยังสรุปไม่ได้ ต้องดูด้วยตา

`sch_run_drc(strict: true)` คืนค่า **`false`** ทั้งแบบ `userInterface: false` และ `true` (รัน 3 ครั้ง ผลเดิม ยืนยันว่าไม่ใช่หลุดการเชื่อมต่อ)

⚠️ **แต่ `false` แปลว่าอะไรยังไม่ชัด** — tool นี้ไม่มี schema บอกความหมายของค่าที่คืน และไม่มีโหมด verbose อาจแปลว่า "ERC พบ error" หรือแค่ "รันไม่สำเร็จ/ไม่คืนรายงาน" ก็ได้

**สิ่งที่ตัดออกไปได้แล้ว:** ตรวจขาของทุก component ที่เสี่ยงแล้ว (Q1, Q3, SW1, U1, P1, USB1) — **ไม่มีขาลอยเลยแม้แต่ขาเดียว** ขาที่ไม่ต่อทุกขาถูกติดธง No-Connect ไว้ถูกต้อง และทุก net ในเน็ตลิสต์มีขาเชื่อมอย่างน้อย 2 ขา

**เหลือให้ทำ:** เปิดหน้าต่าง ERC ใน EasyEDA แล้วส่งรายการ error มา ถ้าว่างเปล่า = ผ่านจริง และข้อนี้ตัดทิ้งได้

# ⚠️ ส่วนที่ต้องตรวจ PCB ใหม่ (ข้อมูลไม่น่าเชื่อถือ)

ระหว่างการตรวจ พบว่า **ตำแหน่ง component กับตำแหน่ง pad ที่อ่านมาไม่สอดคล้องกัน** เช่น ระบบบอกว่า `Q1` อยู่ที่ (2460, −3965) mil แต่ pad ของ CH221K (pin1 = net `$1N74`, pin3 = ไม่มี net) กลับอยู่ที่ ~(1170, −2300) mil

สาเหตุที่เป็นไปได้: การอ่าน 2 ครั้งเกิดคนละช่วงเวลาและอาจเป็น **คนละเอกสาร PCB** (มีการสลับ tab / reconnect คั่นกลาง)

**ผลที่ตามมา — ข้อสรุปเชิงตำแหน่งต่อไปนี้ต้องอ่านใหม่ทั้งหมดก่อนเชื่อ:**
- รูสกรู M3 4 มุม (รอบก่อนสรุปว่าไม่มี)
- รูขาตั้ง ⌀7.5mm MOUNT1 และระยะ clearance
- มุม 90° 5 จุด และพิกัดที่ระบุ
- ระยะ decoupling cap
- board outline

**สิ่งที่ยังเชื่อได้ 100%** คือทุกอย่างในเอกสารนี้ที่มาจาก **netlist และรายการชิ้นส่วน** (B1–B5, W1, W4–W10 และหมวด PASS ทั้งหมด) เพราะมาจากการอ่านครั้งเดียวที่สอดคล้องกันในตัวเอง

**วิธีตรวจใหม่:** เปิด `PCB1_1` ให้ active → กด `Claude → Connect Claude` → อย่าสลับ tab ระหว่างตรวจ

# ลำดับการแก้ที่แนะนำ

1. **B1** ย้าย U1.1 → 3V3 (ถ้าไม่แก้ บัซเซอร์ใช้งานไม่ได้เลย)
2. **B2** สลับ P1 pin1 ↔ pin2 (ถ้าไม่แก้ จอพังตอนเสียบครั้งแรก)
3. **B4** เปิดหน้าต่าง ERC ส่งรายการ error มา (หรือยืนยันว่าว่าง)
4. **W1** ลด R11 → 100–150Ω · **W8/W9** แก้รหัส LCSC + Value ของ R10
5. **W2/W3** เพิ่ม bulk + decoupling cap
6. **B3** Import Changes from Schematic ผ่าน GUI
7. **W4** ตั้ง Net Class POWER 0.80mm แล้ว re-route
8. ตรวจ PCB geometry ใหม่ทั้งหมดบน PCB1_1
