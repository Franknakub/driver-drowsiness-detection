Driver Drowsiness Detection ระบบตรวจจับความง่วงของคนขับด้วยกล้อง + TinyML — แนวทางต่อ Schematic

กล้องจับภาพ→วัดการหลับตา→รวมกับ IMU→ตัดสินระดับ→เตือนด้วยเสียง

01ระบบทำงานยังไง

อุปกรณ์แบ่งเป็น 3 กลุ่ม — ตัวรับข้อมูล ตัวประมวลผล และตัวแจ้งเตือน โดยมี IR LED เป็นตัวช่วยพิเศษที่ทำงานเฉพาะตอนมืด

ทำไมไม่ใช้ไฟส่องหน้าปลุก

ตาที่ปรับให้ชินกับความมืดแล้ว เจอไฟสว่างจ้าจะมองไม่เห็นถนนไปราว 5–10 วินาที และคนที่กำลังงีบจะสะดุ้งจนอาจหักพวงมาลัย คนง่วงที่มองไม่เห็นถนน อันตรายกว่าคนง่วงที่ยังมองเห็น ระบบนี้จึงใช้เสียงเป็นตัวปลุกหลัก และ IR LED ทำหน้าที่ให้กล้องมองเห็นเท่านั้น

ทำไม OLED กับ MPU6050 ใช้ขาเดียวกันได้ — I2C เป็นบัสที่ต่อขนานกันได้หลายตัว แต่ละตัวมีที่อยู่ไม่ซ้ำกัน (OLED = 0x3C, MPU6050 = 0x68) ESP32 จึงเรียกทีละตัวได้บนสายคู่เดียว

ทำไมต้องมี IMU ด้วย — กล้องพลาดได้หลายกรณี เช่น คนขับใส่แว่นกันแดด แสงจากไฟหน้ารถสวนทำให้ภาพขาว หรือหันหน้าออกจากกล้อง IMU ไม่สนใจแสงเลย จับได้แค่การเคลื่อนไหว จึงเป็นตัวสำรองที่ทำงานได้เสมอ

04แนวทางต่อ Schematic

แยกเป็นบล็อก ทำทีละบล็อกแล้วตรวจก่อนไปบล็อกถัดไป ป้ายชื่อ net ให้สะกดเหมือนกันเป๊ะทุกที่ ตัวพิมพ์ใหญ่เล็กมีผล

หลักการที่ใช้ทั้งบอร์ด — บอร์ด GOOUUU เสียบลงบน socket U5/U6 ซึ่งทำให้รูเต็ม อุปกรณ์ที่จะเสียบเพิ่มทีหลังจึงต้องมี header ของตัวเองบน PCB โดยลากสายจาก socket มาเข้า header นั้น

P1 เสร็จแล้ว

บัส I2C เส้นเดียวรองรับทั้งสองตัว วาง header สองชุดขนานกันบนเส้นเดิม

  1. วาง header 1×4 ตัวใหม่ ตั้งชื่อ J4 (ค้นหา HDR-TH_4P-P2.54-V-M)
  2. ลากสายจาก J4 ไปเข้า net ทั้ง 4 ตามตาราง — ใช้ net เดียวกับ P1 ได้เลย
  3. Pull-up R4/R5 4.7kΩ มีอยู่แล้ว ไม่ต้องเพิ่มอีก

ก่อนวาด หยิบโมดูลจริงมาอ่านตัวหนังสือข้างขา ลำดับขาไม่เหมือนกันทุกยี่ห้อ — ต่อ VCC กับ GND สลับกันคือพังทันทีที่เสียบ

ใช้โมดูลสำเร็จรูป KY-012 Active Buzzer ซึ่งมีทรานซิสเตอร์ขับในตัวแล้ว จึงไม่ต้องมี MOSFET บนบอร์ด

  2. วาง header 1×3 ตั้งชื่อ J2 (HDR-TH_3P-P2.54-V-M)
  3. เพิ่ม R 10kΩ 0805 จาก GPIO14 ลง GND กันบัซเซอร์ร้องตอนบูต

ต้องเป็น Active ไม่ใช่ Passive — KY-012 คือ active (จ่ายไฟแล้วร้องเลย) ส่วน KY-006 เป็น passive ต้องส่ง PWM ถึงจะมีเสียง

จุดที่พลาดแล้วบอร์ดใช้ไม่ได้เลย

คอนเนคเตอร์ FPC มีสองแบบ — top contact กับ bottom contact ถ้าเลือกผิดด้าน สายกล้องจะเสียบกลับข้าง แก้ไม่ได้ ต้องสั่งบอร์ดใหม่ ตรวจให้ชัดในหน้าสินค้า LCSC ก่อนวาง

ต้องทดสอบก่อนสั่ง PCB — โมดูล OV5640 ส่วนใหญ่มี IR-cut filter ที่บล็อกแสงอินฟราเรดทั้ง 850 และ 940nm ถ้าโมดูลที่มีอยู่มีฟิลเตอร์ IR LED ทั้ง 4 ดวงจะไม่ช่วยอะไรเลย ให้ทดลองส่อง IR ในที่มืดแล้วดูว่าภาพสว่างขึ้นไหม ถ้าไม่ ต้องหาโมดูลรุ่น no IR filter หรือ night vision

  • ใส่ C 100nF ใกล้ขาไฟของทุก IC
  • ใส่ฟิวส์ 1A และ diode กันต่อกลับขั้วที่อินพุต — ไฟรถมีสัญญาณรบกวนสูงและอาจกระชากถึง 40V ตอนสตาร์ท

ห้ามให้ VBUS จาก USB ต่อตรงกับ net 5V ที่ MP1584EN จ่ายอยู่ ไฟสองแหล่งจะตีกัน ถ้าจะเก็บพอร์ต USB ไว้ต้องมี Schottky diode กั้น หรือตัดภาค USB-C กับ CH221K ออกไปเลยเพราะบอร์ด GOOUUU มี USB ของตัวเองอยู่แล้ว

05รายการงานคงเหลือ

เรียงตามลำดับที่ควรทำ — ข้อที่ติ๊กแล้วคือส่วนที่ตรวจ netlist แล้วผ่าน

  • I2C — P1 OLED header + pull-up 4.7kΩ ต่อครบ
  • IR LED — ขั้ว ทิศกระแส และขา Q3 ถูกต้อง
  • LED เขียว GPIO47 · LED แดง GPIO40
  • R16–R19 เปลี่ยนเป็น 120Ω ขนาด 1206
  • ลบสายค้างที่ทำให้ GPIO21 ลัดกับ GPIO42 — คลิกเส้นที่ออกจาก U6 pin 34 แล้วดูว่าสาย SCL สว่างขึ้นด้วยไหม
  • ลบ Q2, R1, R2 แล้ววาง header J2 1×3 สำหรับบัซเซอร์
  • วาง header J4 1×4 สำหรับ MPU-6050
  • เพิ่มปุ่ม USER + pull-up + debounce cap
  • ทดสอบ IR กับกล้องจริง ก่อนตัดสินใจเรื่อง FPC
  • วาง FPC 24P — ตรวจ top/bottom contact ให้ชัด
  • เพิ่มภาคจ่ายไฟ MP1584EN + AMS1117 + ฟิวส์ + diode
  • ตัดภาค USB-C และ CH221K ออก
  • ผูก LCSC part number ให้ครบทุกตัว แล้วเช็ค stock
  • รัน DRC ให้ผ่านหมด ไม่มี net ที่มีขาเดียว

ก่อนกดสั่งผลิต ตรวจสามอย่างนี้ให้ครบ — ทิศทาง FPC contact, ค่าตัวต้านทานทุกตัวและขนาด package, และ DRC ต้องไม่เหลือ error ทั้งสามข้อนี้คือสาเหตุที่บอร์ดกลับมาแล้วใช้ไม่ได้บ่อยที่สุด
