2ML: ยังขาดขั้นตอนหาตา

โมเดลรับภาพตาขนาด 96×96 แต่กล้องส่งมาทั้งเฟรม เอกสารเดิมยังไม่ได้บอกว่าจะ crop ตาออกมาอย่างไร มี 3 ทางให้เลือก

ทางวิธีข้อดีความเสี่ยง
A MVPกรอบตาคงที่ ตั้งครั้งเดียวจากหน้าเว็บง่ายที่สุด ใช้ MRL train ได้เลยถ้าขยับหัว ตาจะหลุดกรอบ
B อัปเกรดใช้ face detection ของ ESP-DL ซึ่งให้จุดตำแหน่งตา แล้วค่อย cropแม่นที่สุด ยังใช้ MRL ได้ไม่มี ESP-DL มากับ core 3.3.12 อาจต้องย้ายไป PlatformIO/ESP-IDF
CEdge Impulse FOMO ตรวจ eye_open/eye_closed จากทั้งเฟรมอยู่ใน Arduino ได้ ใช้โมเดลเดียวต้องถ่ายและ label ภาพเองหลายร้อยรูป ตาเล็กมากเมื่อเทียบกับ grid

Train

  • ใช้ MRL Eye dataset (grayscale มีภาพ IR) แยก 2 class คือตาเปิดกับตาปิด
  • MobileNetV2 96×96 grayscale INT8 บน Edge Impulse แล้ว export เป็น Arduino library
  • สัปดาห์ 1 ต้องเช็คว่า library ที่ได้ compile กับ core 3.3.12 ผ่าน

Fine-tune ด้วยภาพจริง

  • ภาพ MRL ต่างจากภาพ OV5640 + IR ของเรา ถ้าไม่ fine-tune โมเดลมักแม่นบน PC แต่พังบนบอร์ด
  • เก็บภาพผ่านโหมดเก็บข้อมูลบนเว็บ (ข้อ 4)
  • วัดผลด้วยภาพของเราเอง และทั้ง pipeline ต้องได้อย่างน้อย 5 fps

4เว็บบนตัวบอร์ด

ESP32 เป็นเว็บเซิร์ฟเวอร์เอง เพราะในรถไม่มีเน็ตบ้าน บอร์ดจะต่อ hotspot มือถือก่อน ถ้าต่อไม่ได้ภายใน 10 วินาทีจะเปิด AP ของตัวเองชื่อ Drowsy-XXXX ทั้งสองแบบเข้าผ่าน drowsy.local ได้

หน้ามีอะไร
Dashboardระดับเตือน, กราฟ P(closed), PERCLOS, fps, ค่าแสง, สถานะ IR อัปเดตสดผ่าน WebSocket
Live viewภาพสดพร้อมกรอบตา เปิดเฉพาะตอนกดดู เพราะกิน CPU

Calibrate & Dataตั้งกรอบตา (ทาง A) และปุ่ม "ตาเปิด" / "ตาปิด" สำหรับเก็บภาพ crop ไปใช้ fine-tune

  • Library: ESP32Async/ESPAsyncWebServer + AsyncTCP ซึ่งเป็นตัวที่ยังมีคนดูแลอยู่
  • ไฟล์หน้าเว็บ: gzip ฝังใน firmware หรือเก็บใน FFat (partition นี้เป็น FAT 9.9 MB ไม่ใช่ LittleFS)
  • Stream: ให้กล้องส่ง grayscale ตามที่ ML ต้องการ แล้วใช้ frame2jpg() แปลงเฉพาะเฟรมที่จะส่ง ที่ 2–5 fps ขนาด QVGA ไม่ควรให้กล้องส่ง JPEG มาตรงๆ เพราะ ML ต้อง decode กลับอีกรอบ และให้คัดลอกเฟรมที่ย่อแล้วไว้ใน buffer กลาง ไม่ส่ง fb ข้าม core

5แจ้งเตือนเข้ามือถือ

LINE Notify ปิดบริการไปแล้วตั้งแต่ มี.ค. 2025

แต่เอกสารเดิมยังเขียนว่าจะใช้ ต้องเลือกช่องทางใหม่

  • Telegram Bot แนะนำ ฟรี ส่งด้วย HTTPS POST ครั้งเดียว
  • LINE Messaging API ต้องสร้าง Official Account และมีโควตาฟรีจำกัด
  • ต้องต่อ hotspot ถึงจะส่งได้ ถ้าอยู่โหมด AP ให้เก็บคิวไว้ส่งทีหลัง
  • ต้องส่งจาก task แยก เพราะ HTTPS ใช้เวลา 1–2 วินาที จะไปบล็อก vision loop

6IR LED

  • ทดสอบ IR filter ให้จบก่อนอย่างอื่น ถ้ากล้องมีแผ่นกรอง IR โหมดกลางคืนทั้งหมดจะใช้ไม่ได้
  • R16–R19 ไม่เกินพิกัด BOM ชุดที่สั่งผลิตใช้ 120Ω ขนาด 1206 (0.25 W) กระแสดวงละ ~29 mA ทำให้ตัวต้านทานรับแค่ ~0.1 W เปิด IR ค้างได้ ไม่ต้องจำกัด duty
  • LDR: ใส่ hysteresis กัน IR กระพริบตอนแสงก้ำกึ่ง และต้องคาลิเบรต ADC ใหม่ เพราะ R1 ย้ายไปต่อ 3V3 แล้ว

ห้ามใช้ PLA กับตัวจริง

PLA เริ่มนิ่มที่ประมาณ 55–60°C แต่ในรถกลางแดดร้อนได้ถึง 70–80°C กล่องจะบิดจนกล้องเปลี่ยนมุม ขั้นต่ำให้ใช้ PETG ซึ่งทนได้ราว 80°C และปริ้นง่ายพอๆ กับ PLA ถ้ามี ASA จะดีกว่าเพราะทนร้อนและทน UV ได้ดีกว่า PLA ใช้ได้เฉพาะชิ้นทดลองเช็คขนาด

3. ปริ้นทดลองใช้ PLA ปริ้นเฉพาะส่วนที่ต้องพอดี เช่น รางรับบอร์ด ช่อง USB-C แนวรู IRสัปดาห์ 3
4. ทดสอบรวมเช็คว่ากล้องไม่เห็นแสง IR รั่ว, ความร้อนข้างใน, มุมกล้องมองเห็นหน้าคนขับสัปดาห์ 3
5. ตัวจริงปริ้นด้วย PETG / ASA แล้วติดตั้งในรถสัปดาห์ 4
  • ส่วนติดตั้งในรถ: ฝังน็อตเกลียว 1/4"-20 (เกลียวขาตั้งกล้อง) หรือทำขาแบบ GoPro ไว้ที่ฐาน จะใช้กับขาจับมือถือในรถที่มีขายทั่วไปได้ และปรับมุมได้โดยไม่ต้องออกแบบข้อต่อเอง

9เรื่องที่ต้องตัดสินใจก่อนเริ่ม

  1. วิธีหาตา: A แล้วค่อย B แนะนำ หรือไป C เลย
  2. เครื่องมือ: ใช้ Arduino IDE ต่อ หรือย้ายไป PlatformIO / ESP-IDF ขึ้นกับข้อ 1 ถ้าเลือก B น่าจะต้องย้าย
  3. ช่องทางแจ้งเตือน: Telegram แนะนำ / LINE Messaging API / ไม่ทำ
  4. ขอบเขตเว็บ: อยู่บนบอร์ดอย่างเดียว แนะนำ หรืออยากมี cloud เก็บประวัติด้วย
  5. PCB จาก JLCPCB มาถึงหรือยัง: ถ้ายัง สัปดาห์ 1–3 ทำบน dev board + breadboard ไปก่อนได้
  6. เครื่องปริ้น 3D: มีเครื่องเองหรือต้องส่งร้าน และมีเส้น PETG หรือ ASA ไหม
  7. ตำแหน่งติดตั้งในรถ: บนคอนโซลหน้า, กระจกหน้า หรือเสา A
  8. จอ OLED: ต้องหันหาคนขับในด้านเดียวกับกล้องใช่ไหม
