#งานสถานะอธิบายใครทำ
1. ทดสอบในรถและโมเดล (สำคัญที่สุด)
1.1เก็บภาพตาในรถตอนจอดยังไม่เริ่มโมเดลตอนนี้ train จาก MRL ซึ่งพลาดกับกล้องเรา (ตาซ้ายของภาพตอบว่าปิดถูกแค่ 19–29%) ต้องใช้ภาพจริงจากตำแหน่งติดกระจก · สคริปต์เก็บภาพเตรียมไว้แล้วผู้ใช้
1.2ทดสอบหาหน้าจากมุมกล้องจริงยังไม่เริ่มกล้องบนกระจกอยู่สูงกว่าตาและมองลง มุมนี้ยังไม่เคยลอง ถ้าหาหน้าไม่เจอ ระบบทั้งหมดก็ใช้ไม่ได้ · ทำพร้อม 1.1ผู้ใช้
1.3fine-tune โมเดลแล้วใส่ลงบอร์ดรอ 1.1train ต่อจากโมเดลเดิมด้วยภาพในรถเท่านั้น ที่โต๊ะเคยลองแล้ว ตาซ้ายดีขึ้นเป็น 93–95%Claude
1.4ปรับเกณฑ์จากข้อมูลจริง (วิธี ข)รอ 1.1เกณฑ์ส่วนใหญ่ เช่น PERCLOS 15/25% และตาปิด 1.5/3 วิ ตั้งไว้ที่โต๊ะ ต้องเล่นข้อมูลในรถซ้ำเพื่อหาค่าที่เตือนพลาดน้อยสุดClaude
1.5คาลิเบรต LDR ในรถยังไม่เริ่มห้องมืดอ่านได้ ~2900 ส่วนเกณฑ์เปิด IR คือ 2800 · ในรถกลางวันกับกลางคืนอาจต่างจากนี้มากผู้ใช้วัด · Claude แก้ค่า
1.6ขับจริง 20–30 นาทีรอ 1.3 + 4.1ทดสอบว่าเตือนผิดบ่อยแค่ไหนตอนขับปกติ · ห้ามหลับตาขณะรถวิ่ง ให้ทดสอบหลับตาตอนจอดเท่านั้นผู้ใช้
2. เรื่องที่รอผู้ใช้ตัดสินใจ
2.1ก้มหัวหลับทันทีรอตัดสินใจถ้าตาปิดไม่ถึง ~1.2 วิแล้วหน้าหายไปเลย ระบบเตือนแค่ Distraction (เสียงสั้น) · ข้อเสนอคือ "ตาปิดแล้วหน้าหาย ≥3 วิ = ระดับ 3" (เสียงยาว ปิดเสียงไม่ได้)ผู้ใช้
2.2ท่าเพิ่มในสคริปต์เก็บภาพรอตัดสินใจเพิ่ม "หลับแล้วก้ม" และ "ก้มดูมือถือ" เพื่อใช้แยกสองกรณีนี้ใน 1.4 · ควรตัดสินก่อนทำ 1.1 จะได้ไปรถครั้งเดียวจบผู้ใช้
3. Firmware
3.1จอ OLEDยังไม่เริ่มฮาร์ดแวร์ผ่านแล้ว (เจอที่ 0x3C) แต่ DrowsyFW ยังไม่แสดงอะไรบนจอ · เสนอให้แสดงระดับความง่วง, PERCLOS และสถานะ WiFi/SyncClaude
3.2ทดสอบ buzzer/LED กับ DrowsyFWยังไม่เริ่มที่ผ่านเมื่อ 23 ต.ค. คือ BenchTest ยังไม่ได้ดูว่าหลับตาแล้ว LED แดงกะพริบ (ระดับ 1) และ buzzer ดังเป็นจังหวะหรือดังยาว (ระดับ 2/3) ถูกต้องไหม · ใช้เวลาไม่ถึง 10 นาทีที่โต๊ะผู้ใช้ + Claude
3.3แจ้งเตือนผ่าน Telegramยังไม่เริ่มอยู่ในแผนเดิม (LINE Notify ปิดบริการแล้ว) ยังไม่ได้ทำ · ถ้าเวลาไม่พอตัดออกได้Claude
3.4ปุ่มบนบอร์ดไม่รีบไม่มีปุ่ม USER ตอนนี้ปิดเสียงได้ทางเว็บอย่างเดียว · ทางเลือกคือใช้ปุ่ม BOOT บนโมดูลClaude
3.5เฟรมกล้องเสีย ~17%ไม่รีบไม่เกี่ยวกับ PCB และยังได้ ~7 fps ไม่กระทบการทำงาน—
3.6buzzer เบาที่ 3.3Vไม่รีบตัวเป็นรุ่น 5V ถ้าในรถได้ยินไม่ชัดให้เปลี่ยนเป็น TMB12A03ผู้ใช้

  6. ปิดเครื่อง = Trip จบ (Device ไม่ต้องรู้ตัว) · Trip Summary คำนวณทั้งบน Device (ไฟล์ .m) และบน cloud (view trip_summary) ด้วยนิยามเดียวกัน

  • HumanFaceDetect (MSR + MNP) ให้กรอบหน้าและจุด 5 จุด เราใช้แค่จุดตาซ้าย/ขวา
  • Eye Region = สี่เหลี่ยมจัตุรัสรอบจุดตา ขนาดตามระยะห่างระหว่างตาสองข้าง จึงปรับตามระยะห่างจากกล้องเอง
  • หาหน้าไม่เจอ ≥ 3 วิ → Distraction
  • เฟรมจากกล้องใช้ RGB565 HVGA 480×320 (ตาใหญ่ขึ้น ~1.5 เท่าจาก QVGA · ระยะระหว่างตา ~37 px) ส่วนโมเดลตาใช้ grayscale ที่แปลงจาก crop
  • Eye Region ด้าน = 0.8 × ระยะระหว่างตา · P(ตาปิด) เฉลี่ยสองข้าง
  • ใน 0.2.5 หาหน้าเจอราวครึ่งหนึ่งของเฟรม · logic ความง่วงจึงถือ Eye State เดิมไว้ช่วงสั้นๆ (ข้อ 5)
  • left_eye ของ esp-dl คือตาที่อยู่ซ้ายของภาพ (= ตาขวาของคนขับ)

ผลทดลอง 16 ต.ค. ผ่าน

  • compile ผ่าน ใช้ libespressif__esp-dl.a จาก core + โมเดล msr/mnp จาก esp-dl v3.3.11 (191 KB)
  • หาหน้า ~55 ms (เจอหน้า) / ~47 ms (ไม่เจอ) · คอขวดคือกล้อง 7.9 fps ที่ QVGA
  • ระดับตา ตรงหน้าหรือเยื้องข้าง 30°: เจอ 100% · หลับตา: 92%
  • กล้องต่ำกว่าหน้าแล้วมองขึ้น: 20% ใช้ไม่ได้
  • เอียงคอ ≥ 20° หาไม่เจอ ต้องหมุนภาพชดเชยตามมุมเส้นตา + ลดเกณฑ์คะแนน MSR เป็น 0.30 จึงได้ 92–100% ที่ 30°
  • ซอร์สทดลองอยู่ที่ ~/Documents/Arduino/FaceSpike/
ภาพจากกล้องตะแคง 90° (แก้แล้วใน 0.2.5)

OV5640 หมุน 90° เองไม่ได้ และกล่องแนวนอนที่เลือกยังได้ภาพตะแคง เดิมหมุนทั้งเฟรมก่อนหาหน้า (~32–38 ms ที่ HVGA) ตอนนี้ esp-dl หยิบเฉพาะพิกเซลที่โมเดลต้องใช้ผ่านแผนที่หมุน (face_view.h) ได้ input ตรงกับทางเดิมทุก byte · rotate + detect ลดจาก 82.7 เหลือ 52 ms · fps ~7

ตาในภาพเล็ก (ตัดสินแล้ว)

เปลี่ยนกล้องเป็น HVGA และ train โมเดลที่ 32×32 แทน 64×64 ให้ใกล้ขนาดตาจริงในภาพ

Train โมเดลตาเปิด/ปิด

  1. ข้อมูล: MRL Eye Dataset (84,898 ภาพ, 37 คน) วางไว้ที่ ml/data/ · label อยู่ในชื่อไฟล์ eyestate 0 = ปิด, 1 = เปิด
  2. แบ่ง train/val/test ตาม subject ID ไม่สุ่มรายภาพ ไม่งั้นความแม่นสูงเกินจริง
  3. Preprocess: grayscale → bilinear 32×32 → int8 (gray − 128) แบบจำนวนเต็มล้วน · ml/preprocess.py กับ eye_preprocess.h ให้ผลตรงกันทุก byte (test_preprocess.py + golden test บนบอร์ด)
  4. โมเดล: ลอง 12 แบบ × 3 seed (ml/output/experiments/) · เลือก deep2_half_p8: test accuracy 96.2%, recall ตาปิด 94.3% (base เดิม 93.6% / 91.3%) · 18,409 params · 2.43 M MACs · 27.5 KB · arena 29,324 B ยังพอดี RAM ภายใน
  5. Export: INT8 แบบ full-integer ใช้ representative dataset → .tflite → model_data.h · op ที่ใช้: CONV_2D, MAX_POOL_2D, MEAN, FULLY_CONNECTED, LOGISTIC
  6. เกณฑ์: วิเคราะห์ threshold บน val/test แล้วใช้ hysteresis ปิด ≥ 0.5 · เปิด < 0.3 · ระหว่างนั้น = ไม่แน่ใจ (ml/output/threshold_note.md)
  7. ผลบนบอร์ด (ทดสอบตามเสียงบี๊บ): โมเดลเดิมจับตาปิดได้ 4/21 → deep2_half 14/17 · ตาเปิดไม่ถูกทายเป็นตาปิด · หันหน้าออกถูก 100%
  8. Fine-tune (ถ้าจำเป็น): โหมด dataset เก็บภาพตา 64×64 กรอบกว้างพร้อม label จากจังหวะเสียงบี๊บ ให้ครบกลางวัน กลางคืน ใส่แว่น และไม่ใส่แว่น · ตัดสินหลังทดสอบในรถ
บทเรียนจาก DrowsyFW ที่ลบไปแล้ว

ตัวเดิมใช้โมเดลขนาด 609 KB ใช้เวลา 223 ms ต่อเฟรม (ได้ ~4 fps) และตอบ P(ตาปิด) = 1.00 ทุกเฟรม สาเหตุที่น่าจะเป็นคือ preprocessing ไม่ตรงกับตอน train หรือ crop ไม่ได้อยู่บนตา ทั้งสองเรื่องนี้ golden test และภาพสดที่วาดกรอบไว้จะจับได้ backup ของตัวเดิมอยู่ที่ Desktop\esp32-flash-backup\

5Logic ความง่วง

Eye State ของแต่ละเฟรมได้จาก P(ตาปิด) เฉลี่ยสองข้าง: ≥ 0.5 = ปิด, < 0.3 = เปิด, ระหว่างนั้น = ไม่แน่ใจ, หาตาไม่เจอ = มองไม่เห็น · DrowsinessJudge (drowsiness.cpp) นับทุกอย่างเป็นเวลาจริงระหว่างเฟรม (dt) ไม่นับเป็นจำนวนเฟรม · เกณฑ์อยู่ใน drowsy_config.h (ยังปรับจากหน้าเว็บไม่ได้)

สถานะเงื่อนไข (ค่าเริ่มต้น)Alertปิดเสียงได้
Level 0 ปกติ—LED เขียว—
Level 1 เริ่มล้าPERCLOS (60 วิ) ≥ 15%LED แดงกระพริบ (+ OLED เมื่อทำเสร็จ)—
Level 2 ง่วงตาปิดต่อเนื่อง ≥ 1.5 วิ หรือ PERCLOS ≥ 25%LED แดงกระพริบ + buzzer เป็นจังหวะได้
Level 3 Microsleepตาปิดต่อเนื่อง ≥ 3 วิLED แดงกระพริบ + buzzer ดังค้างไม่ได้
Distractionหาหน้า/ตาไม่เจอ ≥ 3 วิ · เริ่มนับหลังเห็นตาครั้งแรกหลังเปิดเครื่อง · ไม่เห็นตาเกิน 60 วิ = คนขับลงจากรถ หยุดเตือนจนกว่าจะเห็นอีกLED แดงกระพริบ + buzzer สั้นๆได้
UnmonitoredEye State เป็น "ไม่แน่ใจ" ≥ 5 วิ (เช่น แว่นดำ)LED ดับทั้งคู่ · ไม่มี Alert เรื่องความง่วง—
  • PERCLOS: 60 ช่อง ช่องละ 1 วิ นับเฉพาะเวลาที่ตัดสินได้ว่าเปิดหรือปิด · ใช้ได้เมื่อเห็นตารวม ≥ 30 วิ · ลดระดับเมื่อต่ำกว่าเกณฑ์ 2% (hysteresis)
  • ตาปิดต่อเนื่อง ทนต่อเฟรมที่ผิดพลาด: หาหน้าไม่เจอ ≤ 0.5 วิ ถือสถานะเดิม · "ไม่แน่ใจ" คั่นได้ ≤ 1 วิ · ช่องว่างรวมที่หาหน้าไม่เจอเชื่อมได้ ≤ 2 วิ · ต้องเห็นตาเปิดต่อเนื่อง ≥ 0.3 วิ จึงตัดช่วงตาปิด (โมเดลตอบ "เปิด" ผิดบางเฟรมขณะหลับตา)
  • Alert หยุดเอง เมื่อลืมตาต่อเนื่อง ≥ 1 วิ · ระดับ 3 ค้างต่อแม้หัวก้มจนหาหน้าไม่เจอ · ระดับที่มาจาก PERCLOS ลดลงเองเมื่อ PERCLOS ต่ำกว่าเกณฑ์
  • Event (ระดับเปลี่ยน, Microsleep, Distraction + ได้เวลาจริงจาก log task) ส่งผ่านคิวให้ log task เขียนลง FFat
  • ทดสอบ: firmware/tests/drowsiness_test.cpp 74 ข้อ ป้อนลำดับเฟรมจำลอง 150 ms
  • ปิดเสียง จาก Device Dashboard ปิดได้เฉพาะ buzzer ของระดับ 1–2 และ Distraction (ค่าเริ่มต้น 5 นาที) ส่วน LED/OLED ยังทำงานอยู่
  • ต้องอ้างอิงเปเปอร์เรื่องเกณฑ์ PERCLOS ในรายงาน · blink rate แสดงในเว็บเท่านั้น ไม่ใช้ตัดสิน

6ประวัติและการ Sync

บน Device (FFat 3.9 MB)

  • 1 Trip = 3 ไฟล์ใน /trips/: <n>.s header + Sample 16 ไบต์/วิ · <n>.e Event 12 ไบต์ · <n>.m ตำแหน่งที่ Sync แล้ว + Trip Summary + crc (crc เสีย = ถือว่ายังไม่ Sync)
  • เวลาใน record = millis() นับจากบูต · Event TimeKnown จด epoch ตอนได้เวลาจริงจาก NTP หรือ browser ใช้แปลงย้อนหลังได้ทั้ง Trip
  • Sample ~58 KB/ชม. เก็บได้ราว 60 ชั่วโมง · ถึง 80% ลบ Trip ที่ Sync แล้วที่เก่าที่สุด · ไม่ลบข้อมูลที่ยังไม่ Sync
  • ดูบน Device ได้ที่ /trips, /api/trips, /api/trips/<n>
  • เทสต์รูปแบบไฟล์ + Summary บน PC: firmware/tests/trip_record_test.cpp

บน Supabase

  • ตาราง devices, trips, samples (1 แถว = 1 วินาที), events · view trip_summary + ฟังก์ชัน trip_series() สำหรับกราฟ
  • Device ส่งผ่านฟังก์ชัน Postgres ingest (RPC, security definer) ที่เทียบ sha256 ของ DEVICE_SECRET · ส่งซ้ำได้ไม่เกิดแถวซ้ำ (ADR 0003)
  • Driver ผูก Device กับบัญชีตัวเองผ่าน claim_device() แล้วอ่านได้เฉพาะของตัวเอง (Auth + RLS) · ทดสอบแล้วว่า secret ผิดหรือไม่ login เข้าไม่ได้
  • SQL ทั้งหมดอยู่ใน cloud/sql/001_trip_history.sql วางใน SQL Editor ครั้งเดียว · วิธีติดตั้งอยู่ใน cloud/README.md
  • ~0.3 MB ต่อชั่วโมง free 500 MB เก็บได้ราว 1,500 ชั่วโมง
ข้อควรระวัง
  • repo เป็น public: secrets.h และ service key ของ Supabase ห้ามเข้า git เด็ดขาด
  • โปรเจกต์ Supabase แบบ free จะถูก pause ถ้าไม่มีการใช้งาน 7 วัน ให้เช็คก่อนวันเดโม
  • Sync ต้องรันใน task ของ Core 0 เท่านั้น เพราะ HTTPS ใช้เวลา 1–2 วิ ถ้ารันใน vision loop จะบล็อกการตรวจ

สคริปต์ด้านล่างทำที่โต๊ะหรือในรถที่จอดอยู่ ส่วนตอนขับจริงให้คนอื่นขับปกติ เพื่อวัดการเตือนผิดเท่านั้น

กรณีทำอะไรผลที่ควรได้

ตัวเลขที่ใส่รายงาน: recall ของ Microsleep, จำนวนครั้งที่เตือนผิดต่อชั่วโมง, เวลาตั้งแต่หลับตาจนเตือน, fps ทั้ง pipeline และ accuracy ของโมเดลบนชุด test กับบนภาพของเราเอง

10ความเสี่ยงที่ยังเปิดอยู่

  • IR filter ยังไม่ได้ทดสอบ: ถ้ากล้องมีแผ่นกรอง IR โหมดกลางคืนจะใช้ไม่ได้ ทางแก้คือเปลี่ยนเป็นกล้อง NoIR ซึ่งเสียบ FPC เดิมได้
  • ติดกระจกหน้า (ตัดสินแล้ว) แต่ยังไม่ได้ทดสอบในรถ: กล้องมองลงมาจากข้างบน ต่างจากที่โต๊ะ · ดูภาพสดจาก /snapshot.jpg ที่ตำแหน่งจริงก่อนติดถาวร · กล้องต่ำกว่าหน้ามองขึ้นหาเจอแค่ 20%
  • โมเดลยังพลาดตาปิดบางครั้ง (14/17): ภาพในรถต่างจาก MRL มากกว่าที่โต๊ะ · ทางแก้คือโหมด dataset + fine-tune
  • หาหน้าเจอราวครึ่งหนึ่งของเฟรม: logic ชดเชยด้วยการถือสถานะและเชื่อมช่องว่าง แต่ยังไม่ได้ทดสอบ ใส่แว่น, ภาพ IR กลางคืน, หน้าคนอื่น และ false positive จากฉากภายในรถ
