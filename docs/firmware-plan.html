4Vision และ ML

หาตา (ทาง B)

  • HumanFaceDetect (MSR + MNP) ให้กรอบหน้าและจุด 5 จุด เราใช้แค่จุดตาซ้าย/ขวา
  • Eye Region = สี่เหลี่ยมจัตุรัสรอบจุดตา ขนาดตามระยะห่างระหว่างตาสองข้าง จึงปรับตามระยะห่างจากกล้องเอง
  • หาหน้าไม่เจอ ≥ 3 วิ → Distraction
  • ถ้าช้าเกินไป ให้หาหน้าทุก 3–5 เฟรม แล้วใช้ตำแหน่งตาล่าสุดในเฟรมที่เหลือ
  • เฟรมจากกล้องใช้ RGB565 QVGA (เร็วที่สุด) ส่วนโมเดลตาใช้ grayscale ที่แปลงจาก crop
  • left_eye ของ esp-dl คือตาที่อยู่ซ้ายของภาพ (= ตาขวาของคนขับ)

ผลทดลอง 16 ต.ค. ผ่าน

  • compile ผ่าน ใช้ libespressif__esp-dl.a จาก core + โมเดล msr/mnp จาก esp-dl v3.3.11 (191 KB)
  • หาหน้า ~55 ms (เจอหน้า) / ~47 ms (ไม่เจอ) · คอขวดคือกล้อง 7.9 fps ที่ QVGA
  • ระดับตา ตรงหน้าหรือเยื้องข้าง 30°: เจอ 100% · หลับตา: 92%
  • กล้องต่ำกว่าหน้าแล้วมองขึ้น: 20% ใช้ไม่ได้
  • เอียงคอ ≥ 20° หาไม่เจอ ต้องหมุนภาพชดเชยตามมุมเส้นตา + ลดเกณฑ์คะแนน MSR เป็น 0.30 จึงได้ 92–100% ที่ 30°
  • ซอร์สทดลองอยู่ที่ ~/Documents/Arduino/FaceSpike/
ภาพจากกล้องตะแคง 90°

โมเดลหาหน้ารับเฉพาะหน้าตั้งตรง ตอนนี้ต้องหมุนภาพทุกเฟรม (17 ms ที่ QVGA) และ OV5640 ทำได้แค่กลับภาพ หมุน 90° ไม่ได้ ถ้าออกแบบกล่องให้ภาพจากกล้องออกมาตั้งตรง จะไม่เสียเวลาส่วนนี้

ตาในภาพ QVGA เล็ก

ที่ระยะ 40–60 ซม. ตาสองข้างห่างกันแค่ ~30 px ในภาพ Eye Region จึงมีขนาดราว 20–30 px ต้องขยายขึ้นเป็น 64×64 ทางเลือกคือ crop จากภาพความละเอียดสูงกว่า หรือ train โมเดลด้วยภาพขนาดเล็กลง ให้ตัดสินตอนเริ่ม train

Train โมเดลตาเปิด/ปิด

  1. ข้อมูล: MRL Eye Dataset (84,898 ภาพ, 37 คน) วางไว้ที่ ml/data/ · label อยู่ในชื่อไฟล์ eyestate 0 = ปิด, 1 = เปิด
  2. แบ่ง train/val/test ตาม subject ID ไม่สุ่มรายภาพ ไม่งั้นความแม่นสูงเกินจริง
  3. Preprocess: grayscale → 64×64 → normalize · บอร์ดต้องใช้ฟังก์ชันเดียวกันทุกขั้น ทำ "golden test" โดยส่ง crop ชุดเดียวกันเข้าทั้ง PC และบอร์ด แล้วเทียบค่า P ให้ตรงกัน
  4. โมเดล: CNN เล็ก 3–4 ชั้น conv + augmentation (ความสว่าง, blur, พลิกซ้ายขวา) ใน ml/train.ipynb บน Colab
  5. Export: INT8 แบบ full-integer ใช้ representative dataset → .tflite → แปลงเป็น model_data.h
  6. Fine-tune: เก็บภาพจากกล้องเราเองด้วยโหมด dataset ราว 300–500 ภาพต่อ class ให้ครบกลางวัน กลางคืน ใส่แว่น และไม่ใส่แว่น
  7. วัดผล: accuracy/recall ของ class ตาปิด บนชุด test (คนที่ไม่เคยเห็น) + บนภาพของเราเอง · เวลา inference บนบอร์ด
บทเรียนจาก DrowsyFW ที่ลบไปแล้ว

ตัวเดิมใช้โมเดลขนาด 609 KB ใช้เวลา 223 ms ต่อเฟรม (ได้ ~4 fps) และตอบ P(ตาปิด) = 1.00 ทุกเฟรม สาเหตุที่น่าจะเป็นคือ preprocessing ไม่ตรงกับตอน train หรือ crop ไม่ได้อยู่บนตา ทั้งสองเรื่องนี้ golden test และภาพสดที่วาดกรอบไว้จะจับได้ backup ของตัวเดิมอยู่ที่ Desktop\esp32-flash-backup\

5Logic ความง่วง

Eye State ของแต่ละเฟรมได้จาก P(ตาปิด) ที่ผ่าน EMA และ hysteresis: เกิน 0.6 = ปิด, ต่ำกว่า 0.4 = เปิด, ระหว่างนั้น = ไม่แน่ใจ เกณฑ์ทุกตัวนับเป็นวินาทีด้วย millis() ไม่นับเป็นจำนวนเฟรม และปรับได้จาก Device Dashboard

สถานะเงื่อนไข (ค่าเริ่มต้น)Alertปิดเสียงได้
Level 0 ปกติ—LED เขียว—
Level 1 เริ่มล้าPERCLOS (60 วิ) ≥ 15%LED แดงกระพริบ + OLEDได้
Level 2 ง่วงตาปิดต่อเนื่อง ≥ 1.5 วิ หรือ PERCLOS ≥ 25%buzzer เป็นจังหวะได้
Level 3 Microsleepตาปิดต่อเนื่อง ≥ 3 วิbuzzer ดังค้างไม่ได้
Distractionหาหน้า/ตาไม่เจอ ≥ 3 วิbuzzer สั้นๆได้
Unmonitoredเห็นหน้า แต่ Eye State เป็น "ไม่แน่ใจ" ≥ 5 วิ หรือภาพมืด/สว่างเกินไปOLED "ตรวจไม่ได้" · ไม่มี Alert เรื่องความง่วง—
  • Alert หยุดเอง เมื่อลืมตาต่อเนื่อง ≥ 1 วิ ระดับที่มาจาก PERCLOS จะลดลงเองเมื่อ PERCLOS ต่ำกว่าเกณฑ์
  • ปิดเสียง จาก Device Dashboard ปิดได้เฉพาะ buzzer ของระดับ 1–2 และ Distraction (ค่าเริ่มต้น 5 นาที) ส่วน LED/OLED ยังทำงานอยู่
  • ต้องอ้างอิงเปเปอร์เรื่องเกณฑ์ PERCLOS ในรายงาน · blink rate แสดงในเว็บเท่านั้น ไม่ใช้ตัดสิน

6ประวัติและการ Sync

บน Device (FFat 9.9 MB)

  • 1 Trip = 1 ไฟล์ /trips/<boot>.bin ประกอบด้วย header + Sample ขนาดคงที่ ~20 ไบต์ + ไฟล์ Event แยก
  • flush ลง flash ทุก 5–10 วิ ข้อมูลจะหายไม่เกินนี้เมื่อไฟดับ
  • เก็บ cursor ว่า Sync ไปถึงไหนแล้ว
  • header เก็บเวลาจริงทันทีที่ได้จาก NTP หรือ browser
  • เก็บได้ ~130 ชั่วโมง · ถึง 80% ให้ลบไฟล์ที่ Sync แล้วที่เก่าที่สุด · ถ้าเต็มไปด้วยข้อมูลที่ยังไม่ Sync ให้หยุดเก็บ Sample แต่ยังเก็บ Event

บน Supabase

  • trips (device, boot, started_at, time_known)
  • samples (trip, t วินาทีนับจากเริ่ม, eye_state, p_closed, perclos, level, lux, ir)
  • events (trip, t, type, value)
  • trip_summary เป็น SQL view คำนวณจาก samples
  • Device ส่งผ่าน Edge Function ingest ที่ตรวจ secret · Driver อ่านผ่าน Auth + RLS
  • ~0.3 MB ต่อชั่วโมง free 500 MB เก็บได้ราว 1,500 ชั่วโมง
ข้อควรระวัง
  • repo เป็น public: secrets.h และ service key ของ Supabase ห้ามเข้า git เด็ดขาด
  • โปรเจกต์ Supabase แบบ free จะถูก pause ถ้าไม่มีการใช้งาน 7 วัน ให้เช็คก่อนวันเดโม
  • Sync ต้องรันใน task ของ Core 0 เท่านั้น เพราะ HTTPS ใช้เวลา 1–2 วิ ถ้ารันใน vision loop จะบล็อกการตรวจ

9การทดสอบ

ห้ามให้คนขับแกล้งหลับตาขณะรถวิ่ง

สคริปต์ด้านล่างทำที่โต๊ะหรือในรถที่จอดอยู่ ส่วนตอนขับจริงให้คนอื่นขับปกติ เพื่อวัดการเตือนผิดเท่านั้น

กรณีทำอะไรผลที่ควรได้
กระพริบตากระพริบปกติ 1 นาทีไม่มี Alert
หลับ 1 วิหลับตาทีละครั้ง 10 ครั้งไม่มี Alert
หลับ 2 วิ10 ครั้งLevel 2 ทุกครั้ง
หลับ 3 และ 5 วิ10 ครั้งต่อแบบLevel 3 ทุกครั้ง · วัดเวลาตั้งแต่หลับจนเตือน
หันออก / ก้มดูมือถือ4 วิ 10 ครั้งDistraction
แว่นใส / แว่นดำทำซ้ำชุดหลับ 3 วิแว่นใสตรวจได้ · แว่นดำเป็น Unmonitored
กลางคืนทำทั้งชุดในที่มืดโดยเปิด IRผลตามผลทดสอบ IR filter
ขับจริงคนอื่นขับปกติ ≥ 1 ชม.จำนวนครั้งที่เตือนผิดต่อชั่วโมง

ตัวเลขที่ใส่รายงาน: recall ของ Microsleep, จำนวนครั้งที่เตือนผิดต่อชั่วโมง, เวลาตั้งแต่หลับตาจนเตือน, fps ทั้ง pipeline และ accuracy ของโมเดลบนชุด test กับบนภาพของเราเอง

10ความเสี่ยงที่ยังเปิดอยู่

  • IR filter ยังไม่ได้ทดสอบ: ถ้ากล้องมีแผ่นกรอง IR โหมดกลางคืนจะใช้ไม่ได้ ทางแก้คือเปลี่ยนเป็นกล้อง NoIR ซึ่งเสียบ FPC เดิมได้
  • ตำแหน่งติดตั้งยังไม่ได้ตัดสิน: กล้องต้องอยู่ราวระดับตา (มองจากข้างล่าง หาเจอแค่ 20%) ส่วนการติดบนกระจกหน้าซึ่งมองลงมาจากข้างบนยังไม่ได้ทดสอบ · ต้องทดสอบที่ตำแหน่งจริงในรถด้วย FaceSpike/live_view.py ก่อนทำกล่องตัวจริง
  • HumanFaceDetect ยังไม่ได้ทดสอบ: ใส่แว่น, ภาพ IR กลางคืน, หน้าคนอื่น และ false positive จากฉากภายในรถ
  • PCB v2 ยังไม่มาถึง: ถ้าไม่ทัน ให้เดโมบนโมดูล + breadboard
  • buzzer TMB12A05 ที่ 3.3V อาจเบา: ต้องลองฟัง ถ้าเบาให้เปลี่ยนเป็น TMB12A03
